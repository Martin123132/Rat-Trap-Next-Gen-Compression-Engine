# Public preview 5.7.0.12 — installer validation

The public setup contains the same application binary qualified in the
[Library plans record](../../release-manifests/library-plans.json), but Setup
was rebuilt on 27 October 2026 to handle locked Start-menu/desktop shortcuts
more safely during uninstall. The earlier local setup and its records remain
unchanged.

## Results

| Check | Result | Scope |
|---|---|---|
| Original application regression, 21 October | 704 run; 703 passed, one skipped | Windows development host; native symlink privilege unavailable |
| Plan and Library focused rerun, 27 October | 36 passed | Same Windows host |
| Public-upgrade diagnostic, original local setup: first run | 185 checks, one failed | The upgrade succeeded, but one generated QA Start-menu shortcut remained after uninstall; the ordinary-uninstall follow-up did not run |
| Original local setup: repeat | 230 checks passed | Same public 5.7.0.6 to 5.7.0.12 upgrade path under a new isolated QA identity |
| Rebuilt public setup | 243 checks passed | Same upgrade path under another isolated QA identity; nine installed self-test modes; locked-shortcut refusal, repair and both uninstall paths |

The first failure was not discarded: the harness reported a failed shortcut
removal, and a generated QA shortcut was still present after its cleanup even
though its cleanup-error array was empty. The repeat passed, so the immediate
cause of the first removal failure is not established. The normal installed
application and its user files were not changed by these isolated tests.

The public Setup's uninstaller checks the owned shortcuts for locks before
changing the installation, then removes and checks them before removing the
application payload and registration. If Windows still refuses a shortcut
removal, it returns a failure and retains the uninstaller/registration for
a retry. The injected-lock test confirms that a locked QA Start-menu shortcut
prevents payload and registration changes. This does not guarantee cleanup
against every concurrent external filesystem change.

All three installer runs used freshly generated QA identities. The QA-specific
installers contain those isolated identities and therefore are not byte-identical
to the normal public setup. They use the same respective application payloads
and installer recipes. The rebuilt **normal public installer** is 19,206,173
bytes, SHA-256
`DA03D4BB04EE3389D23D0D5DA58AE8EFD5352915925F12039E41A8607E8256A4`.
Its application payload is 19,353,572 bytes, SHA-256
`DE53C59C35ABDA56C7CBCB28490597084F954F31E3A06283B80240B855332FD6`.
The application build receipt's 39 source hashes were rechecked against the
development checkout before publication.

and [fixed isolated QA harness](../../scripts/test_windows_public_library_fixed_installer.ps1)

ordinary read-only source tests, and require their recorded local inputs.

This is same-host Windows 10 testing, not clean Windows 11 acceptance,
independent security certification, signing, Microsoft Store approval,
proof against all races or a new competitive compression benchmark.
